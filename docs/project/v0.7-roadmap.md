# OpenGGF 0.7 Roadmap — Complete campaigns

Updated: 2026-09-08. Implementation baseline: `next` at `ed652eefa`, containing
`develop` at `8392494a0` through merge `973fa3ab8`.

0.7 completes and validates the stock Sonic 1, Sonic 2, and locked-on Sonic 3 &
Knuckles game flows. S3K route completion is the largest remaining implementation
workstream. [0.8](v0.8-roadmap.md) finishes and publishes the added features against
that campaign baseline. No release date is assigned to either line.

The order matters: late levels, stage returns, finales and credits exercise the
same loading, audio, save, rewind, camera and rendering owners used by mods,
racing and widescreen. Component tests can prove a local contract now; full
campaign compatibility needs the actual campaign. Keep existing features under
regression coverage throughout, while deferring their public API freeze and
release-wide compatibility claims until those owners have settled.

This is release planning, not a branch rollover or API publication. `next` still
carries `0.7.prerelease`. The sole Mod API version/publication authority remains
[`mod-api-release-policy.properties`](../../mod-api-release-policy.properties);
it currently describes an unpublished 0.7 candidate. Moving its publication gate
to the 0.8 workstream does not itself rename the API or create a published baseline.

## Scope of a complete character route

The route gate follows the shipped locked-on game's character-specific
progression. A level is not complete merely because it loads or can be crossed
with debug movement. All runtime assets remain ROM-backed. Trace data is
comparison-only except the existing narrowly scoped hardware-readiness contract;
never hydrate gameplay from comparison rows, fit constants to a fixture, or
select behavior by route/frame identity. Use shipped-ROM behavior and its owning
routines to resolve differences.

| Character | Sonic 3 half | Sonic & Knuckles half | Finale |
|---|---|---|---|
| Knuckles | AIZ, HCZ, MGZ, CNZ, ICZ, LBZ | MHZ, FBZ, SOZ, LRZ, HPZ, SSZ | Knuckles' Sky Sanctuary/Mecha Sonic conclusion and outro; DEZ/DDZ are not part of his ROM route |
| Tails | AIZ, HCZ, MGZ, CNZ, ICZ, LBZ | MHZ, FBZ, SOZ, LRZ, HPZ, SSZ, DEZ | Tails' Death Egg conclusion and outro; DDZ is not part of his ROM route |
| Sonic | AIZ, HCZ, MGZ, CNZ, ICZ, LBZ | MHZ, FBZ, SOZ, LRZ, HPZ, SSZ, DEZ | Normal Death Egg conclusion, or DDZ and the good ending when the emerald condition selects it |

For every listed zone, completion includes:

- the correct character layout, start position, object table, collision paths,
  foreground/background deformation, animated art, palette behavior, water,
  music, and level events;
- traversal-critical objects, hazards, badniks, minibosses, bosses, capsules,
  signposts, and character-specific route gates;
- act-to-act, zone-to-zone, special-stage, bonus-stage, death, restart, and
  save/resume transitions used by the route;
- sidekick behavior where the selected team has a sidekick, without allowing
  sidekick defects to block or corrupt the main-character route;
- rewind-safe object and event ownership for gameplay state reachable during
  the route; and
- native 320x224 behavior plus the supported viewport/team compatibility
  contracts already advertised by `next`.

## Milestone 6 — Complete the full-run trace chains

**Status:** chain framework and partial fixtures landed; character chains open

The per-zone `*CompleteRunTraceReplay` classes are necessary segment evidence,
but they do not prove that the engine can carry one campaign continuously. Each
character needs a committed, manifest-backed chain driven through the shared
run-chain owner without bootstrapping every segment as a fresh independent
test.

Required chain matrix:

| Chain | Required terminal boundary |
|---|---|
| Knuckles | AIZ start through the SSZ/Mecha Sonic outro and terminal post-credits movie tail |
| Tails | AIZ start through the DEZ Tails outro and terminal post-credits movie tail |
| Sonic normal | AIZ start through the non-DDZ Sonic outro and terminal post-credits movie tail |
| Sonic emerald | AIZ start through DDZ, the good ending, and terminal post-credits movie tail |

Each chain must:

- consume every manifest segment and transition in order through one continuous
  `GameLoop`, including represented special-stage and bonus-stage detours;
- cross act, zone, death/restart, stage-return, results, finale, ending,
  credits, and title/data-select boundaries using production-raised requests;
- preserve BK2 cursor, lag-loop, frame-counter, input, RNG, SST, respawn, save,
  emerald, art-queue, audio, sidekick, and rewind ownership across handoffs;
- compare every field owned by the fixture and use recorded hardware timing
  only through the permitted scheduling contract;
- report zero unexpected physics, animation, auxiliary-state, transition, or
  hardware-timing errors and no warning or skipped segment; and
- consume the recorded terminal tail instead of declaring success at the end of
  the last ordinary gameplay segment.

Gate: all constituent segment comparators are green; all four chain rows reach
their terminal boundary with the manifest fully consumed; repeated runs produce
the same reports; visual run playback crosses the same boundaries; and the
trace frontier log records the certifying command, commit, run/manifest/log
paths, error count, and terminal result.

## Release boundaries and alternatives

0.7 owns complete stock campaigns and their necessary shared fixes. 0.8 owns
final policy/API design, bundled racing extraction, wider loading optimization,
live FM switching and qualification/publication of already-built additions.
Keep both releases bounded: unrequested editor studio work, hot reload, arbitrary
policy mixing and unsupported stock character/zone combinations remain parked.

Keeping everything in 0.7 would provide one comprehensive release but couple the
campaign schedule to new API, networking/package and performance risks. Shipping
the creator/racing platform first would publish contracts before late-game owners
have been exercised. Campaign first avoids that premature freeze while retaining
ongoing feature regression coverage. If measured loading or audio defects block
a campaign, promote only the necessary fix into 0.7 with evidence; do not pull in
the entire optimization or switching programme.
